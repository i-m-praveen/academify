Most institutions start their testing program with a folder of documents — question papers written for one specific test, used once, and rarely revisited. That approach works until an institution wants to run more than one type of assessment.

## Why a shared repository matters

A well-tagged question bank lets your academic team write a question once and reuse it across:

- Weekly class tests
- Unit and term tests
- Mock exams ahead of an Olympiad
- The Olympiad itself, where applicable

Instead of starting from a blank page for every test cycle, coordinators pull from an existing, vetted pool of questions filtered by subject, topic, and difficulty.

## What good tagging looks like

At minimum, a reusable question bank should support tagging by:

1. **Class, subject, topic, and subtopic** — so questions can be filtered to a specific curriculum area.
2. **Difficulty level** — so a test can be composed to a target difficulty distribution.
3. **Question type** — such as MCQ, text, or match-the-column, since delivery differs by type.

## Getting started

If your institution is still managing questions in spreadsheets or shared documents, the migration path is usually incremental: start tagging new questions as you write them, then bulk-upload your existing bank from a spreadsheet template over one or two test cycles.
